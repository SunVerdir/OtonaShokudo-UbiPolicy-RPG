# 大人食堂（マルチモーダルUBI基盤）政策ゲーム

**OtonaShokudo-UbiPolicy-RPG** — サクッと遊んで、政策形成を学ぶ「人生ロープレ」の提案

![Python 3.10+](https://img.shields.io/badge/Python-3.10%2B-blue) ![runtime dependencies](https://img.shields.io/badge/runtime%20dependencies-none-brightgreen) ![status](https://img.shields.io/badge/status-構想プロトタイプ%20v0.2.1-orange)

> 「人生ゲームの途中で地球が引っくり返ったら、誰が勝ち？」
> それ、絶対つまんない。みんなでルールを創り直そう。

本リポジトリは、『地球人が宇宙人として生き抜くための大人食堂』全8巻で描かれた構想を、政策形成を学ぶための**Python製コマンドライン・ゲーム案**にしたものです。第六巻の公開記事にある「現場の困りごとを政策の問いに変え、人が検証する」という姿勢と、第七巻の原稿で示された「八つの政策構想を人生ゲームのクエストにする」という発想を、遊べる試作品として表現しています。

主な対象は、新ぎゅらりふぃー（α世代）と、ぎゅらりふぃー（Z世代）。世代を固定する学術用語ではなく、著者が提案する呼び名です。若い人を中心に、異なる立場の人が一緒に遊び、問いを立て、ルールの改善案を考えることを想定しています。
α世代・Z世代の実際の参加者によるプレイテストは未実施です。遊びやすさや楽しさは、今後の任意参加のテストで確認します。

> **構想段階の学習用ゲームです。** 自治体の導入、制度の実施、実給付、政策効果を示すものではありません。ゲーム内の人物・出来事・資源量・効果は架空または説明用の仮定です。
> 本作は菅野敦也氏の構想をもとにした試作品で、NEXAや行政等の公式見解・推奨を示すものではありません。

## すぐに遊ぶ

Python 3.10以上が必要です。実行時に追加ライブラリは使いません。

```bash
# リポジトリの作成・公開後に取得する場合
# git clone https://github.com/SunVerdir/OtonaShokudo-UbiPolicy-RPG.git
# cd OtonaShokudo-UbiPolicy-RPG

python -m pip install -e .

# ひとりで遊ぶ
otona-shokudo-rpg --seed 7

# まず短く試す（3ラウンド）
otona-shokudo-rpg --quick --seed 7

# 交代で担当する（複数人）
otona-shokudo-rpg --players ゆい,そら,はる

# 入力なしでデモを観る
otona-shokudo-rpg --demo --seed 7

# 振り返りレポートをMarkdownで保存
otona-shokudo-rpg --seed 7 --save-report game-report.md
```

パッケージをインストールせずに試す場合：

```bash
PYTHONPATH=src python -m otona_shokudo_rpg --demo --seed 7
```

## どう遊ぶか

架空の「大人食堂ワールド」で、食材・予算・人手・電力／通信という限られた資源を使い、災害や物流途絶などの出来事に対応します。ラウンドごとに住民・生産者・運営者・行政・技術者（政策FDE）の視点が巡り、政策アクションを最大2つ選びます。見送りもできます。

AIの提案を含む行動には、人が「味見」（内容を確認）する選択肢があります。ここでのAI行動はゲーム内に登録された固定の行動カードです。実際のAIモデルや外部サービスには接続しません。カード横の `◇` は、今回の困りごとタグと重なる行動を示す目印で、おすすめや解決の保証ではありません。

「有り難う！」は行動カードのタグとイベントの困りごとタグが対応した記録数を基に、AI提案の味見省略分を差し引く**ゲーム内の仮想指標**です。実際の住民の感謝・満足度・同意・政策効果の測定値ではありません。資源コストやカードの効果も、議論のために置いた仮定です。第七巻草稿の一部にある「有り難う！の数を競う」案は、この試作品では採用せず、協力して見落とした声と次の検証課題を探す設計にしています。

標準設定は6ラウンドです。`--quick` は3ラウンド、`--rounds N` は指定したラウンド数で遊べます（両方を指定した場合は `--rounds` を優先）。最初は「世界大恐慌」で、その後のイベント順は乱数で決まります。`--seed` を指定すると同じ標準イベント順を再現でき、省略時もレポートに再戦用seedが表示されます。

| 入力 | できること |
| --- | --- |
| `1 4` | 番号で行動を選ぶ（スペース区切り）。Enterだけで見送り |
| `d` / `m` / `s` | 行動の説明／八構想の段階／いまの状態 |
| `o` | 異論・違和感を記録する |
| `p` | 今回の担当をパスする（担当者名・理由をレポートに保存しない） |
| `q` | 途中で抜け、そこまでの振り返りを見る |

初めて遊ぶときは、①現場の声を読む、②関係するカードを選ぶ（最大2枚）、③理由は任意で一言、④レポートで見落とした声を振り返る、の順です。`Enter` は今回見送り、`p` は担当者名・理由をレポートに残さないパスです。パスした場合も、ゲーム進行に必要な役割・イベント・結果は記録されます。複数人で遊ぶ場合も、本名ではなくニックネームを使ってください。

異論を述べる権利と途中離脱の自由を保ち、勝者を競う設計にはしていません。AIの助言や資源配分も、人が確かめるための学習用ルールです。ゲーム終了後には、同じ出来事順で別の選択を試す再戦コマンドを表示します。

## 八つの政策構想

| # | 構想 | ゲームで考えること | 参照資料に記された段階 |
|---|---|---|---|
| 1 | 大人食堂（マルチモーダルUBI基盤） | 共同食卓、食と生活支援、仮定を置いた試算 | Vision／Draft／ブラウザPoC。実給付・制度導入は未確認 |
| 2 | 子ども食堂DAO | 今日の一食、支援・資金の流れの見える化 | 参考実装・テスト。源内は非接続スタブ |
| 3 | Metaマルシェ | 余剰食材と必要な場所、地域資源の循環 | 構想・プロトタイプ。正式稼働待ち |
| 4 | NFTエコノミー移住特区 | 創作・移住・地域経済 | 政策提言。特区指定・自治体導入は未確認 |
| 5 | 支援のAIドラえもん | 相談の整理、AI案への人の確認 | ローカルMVP。実LLM等は未接続 |
| 6 | メタバース市議会 | 住民参加、熟議、災害時の復旧策 | Vision／構想。MVP・導入は未確認 |
| 7 | OmO城プロジェクト | 地域文化、物語、観光と暮らし | 構想。プレイ可能なゲームは未確認 |
| 8 | 国民皆SI・日本版SIフォース | 知性・行政・研究・地域の連携 | 政策提言。制度・組織の設置は未確認 |

各構想の「段階」は参照資料に記された公開物の成熟度を整理した表示です。このゲームで各政策が実装・実証されたことを意味しません。資源コストや効果も学びのための仮定であり、実データに基づく政策評価ではありません。子ども食堂DAOの「源内」は非接続スタブ、AIアクションは固定カードです。

## ルールの提案・編集

行動カード、イベント、役割、資源、検証課題は `src/otona_shokudo_rpg/data/` 以下のJSONに分けています。プログラミングなしで複製・編集でき、整合性チェックを実行できます。

```bash
cp -r src/otona_shokudo_rpg/data my-rules
otona-shokudo-rpg --rules my-rules --check-rules
otona-shokudo-rpg --rules my-rules
```

テストとルール検査：

```bash
PYTHONPATH=src python -m unittest discover -s tests -v
PYTHONPATH=src python -m otona_shokudo_rpg --check-rules
```

提案の方法と守るべき原則は [`CONTRIBUTING.md`](CONTRIBUTING.md)、サンプルの振り返りは [`docs/sample-report.md`](docs/sample-report.md)、詳細な設計は [`docs/GAME_DESIGN.md`](docs/GAME_DESIGN.md)、公開前チェックは [`PUBLISHING.md`](PUBLISHING.md) を参照してください。変更前に、実在の人・子ども・団体の情報、APIキー、パスワードを入力しないでください。

## 実装範囲と入力情報

この版はコマンドラインで動くローカル試作品です。ブラウザ版、自治体システム連携、実際の給付・支援、外部AIモデル接続は実装していません。ゲーム内容を外部ネットワークへ送信する機能もありません。

プレイヤー名、選択理由、異論、振り返りの記憶は、遊ぶ人が入力した場合にゲームの実行中や保存レポートに含まれます。`p` を選んだラウンドはプレイヤー名と理由をレポートに保存しませんが、画面には担当名が一時表示され、ゲーム進行上の役割・イベント・結果は記録されます。実在の氏名、連絡先、健康・家庭状況など、個人を特定できる情報は入力しないでください。保存したレポートを共有するときは、入力内容を確認してください。
